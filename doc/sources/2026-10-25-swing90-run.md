# 90° Swing Reliability Run — 2026-10-25

Raw evidence for the `koc-swing90` mission. Probe:
`turret_swing90_probe.py` (encoder-driven legs, 0.3 s deadman streaming,
stall abort); CSVs at `/tmp/koc_calib/swing90_full.csv`.

## Setup

Robot static at ~center; obstacle 75 cm dead-ahead (sonar ground truth);
sensors: encoder (PORT_C), color (PORT_1), sonar (PORT_4), kinect depth.
Legs: LEFT 90° → RIGHT 180° → LEFT 90° home, each encoder-driven
(target 11250/22500/11250 ticks at 125 ticks/°).

## Run 1 (0.1 s streaming — the command-queue discovery)

All legs hit 100% but the return missed by **+1641 ticks (+13.1°)**: commands
streamed at 10 Hz while the wrapper consumes ~3.3/s → the 100-deep command
queue backed up ~100 commands per leg, which kept executing after the reset
(the kinect blob at x=589 confirmed the ~13° left overshoot). Software
artifact, not mechanics. **Fix: stream at the consumption rate (0.3 s).**

- **All legs 100% of target** (11288/22518/11263) — no stalls, no cable

- **Return accuracy: 6 ticks (+0.05°)** — mechanical repeatability is
  excellent; the run-1 error was entirely the queue backlog.
- **Color reproduces exactly** (768 → 768) and every pose is distinct
  (734–768 across ±90°) — a viable absolute-angle fingerprint.
- Kinect blob re-centered (x=335 ≈ 320 + parallax); raw 665 ≈ 0.79 m
  (level-view geometry, consistent with the sonar's 75 cm at the sonar's
  lower mounting). Sonar never occluded at any pose.

## Conclusions

1. **±90° swings are reliable** — no travel-limit issues in the tested span;
   the in-turret cables hold.
2. **Return-to-center: 0.05°** with consumption-rate streaming. The v1
   command queue (100-deep, no staleness handling) is the only obstacle to
   doing this all day — the v2 `motord` must drop stale commands
   (noted on koc-v2-motord-driver).
3. **Color = absolute angle sensor** across ±90° (calibration curve in the
   CSV); pairs with the encoder for homing.
4. Tick rate is non-linear in the speed unit: ~7.2 ticks/s/unit at speed 50
   vs ~5.1 at speed 25 — calibrate the PWM→speed curve in v2 `motord`.
